# Промт: админка каталога «Гипс и пламя»

Сделать как в репозитории «Сайты»: статика на GitHub Pages и в Yandex Object Storage, одна Cloud Function, один API Gateway. Правки с `/admin` видны на адресе Яндекса без нового коммита. GitHub Pages остаётся снимком последней сборки.

## Что правится в админке

1. Тексты: шапка, полка на главной, шаги заказа, абзац о мастерской, пустая полка, подписи карточки, title и description.
2. Контакт: ссылка Telegram. Пустая ссылка прячет кнопки «Написать». Заказ по-прежнему уходит готовым текстом в Telegram, заявок в бакет нет.
3. Полки: название, подпись, порядок. Новая полка получает латинский адрес. Полку, на которой есть изделия, удалить нельзя.
4. Изделия: создать, изменить, снять с публикации, удалить. Поля: адрес, название, цена (пусто — «цену напишем»), полка, короткая строка, описание, на главной, порядок, опубликовано, фото. Первое фото — обложка. Фото до 8 штук, в хранилище уходит JPEG.

## Хранение

- Закрытый бакет: `content/site.json` (включая черновики).
- Фото: бакет сайта, ключ `media/{id}/{имя}.jpg`. Их отдаёт тот же шлюз.
- Пароль админки — `ADMIN_PASSWORD`, заголовок `x-admin-password`. В ответы и логи не попадает.
- Секреты репозитория: `YC_SA_JSON`, `YC_FOLDER_ID`, `YC_STORAGE_KEY`, `ADMIN_PASSWORD`.

## API

- `GET /api/content` — публичный JSON: тексты, контакт, полки и только опубликованные изделия.
- `POST /api/admin` — login, load, save-site, save-product, delete-product, sign-upload, delete-image.
- Функция проверяет поля. Адрес изделия: латиница, цифры, дефис, подчёркивание. Чужой ключ фото не принимается.
- Загрузка фото: браузер получает короткую подписанную ссылку и кладёт файл прямо в бакет.

## Сайт

- Сборка из папок `src/content/products` остаётся витриной без API и снимком GitHub Pages.
- На яндексовском сайте скрипт запрашивает `/api/content` и подменяет тексты, контакт и витрину. Если запрос не удался, остаётся собранная страница.
- Новый адрес изделия: шлюз отдаёт оболочку `izdelie/index.html` на `/izdelie/{slug}`. Новая полка открывается через `/katalog/{slug}` той же страницей каталога.
- Первая выкладка кладёт JSON и фото из репозитория. Повторная выкладка не затирает правки админки и добавляет только новые id из репозитория.

## Деплой

- `.github/workflows/deploy.yml`: Pages как сейчас и отдельный job `yandex`.
- Имена ресурсов: `gips-gateway`, `gips-site`, `gips`, бакеты `gips-${folder}` и `gips-data-${folder}`.
- Без обязательных секретов Pages всё равно публикуется, шаг Яндекса останавливается и пишет, какого секрета нет.

## Не делаем

- Корзину, оплату, почту и приём заявок в бакет.
- Правку фотографий мастерской на главной: они остаются в репозитории.
