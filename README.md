# Гипс и пламя

Витрина мастерской: гипсовый декор, свечи, вазы, тарелочки. Статический сайт на Astro 7 и Tailwind 4. Корзины нет — заказ уходит в Telegram с названием и ценой выбранной вещи.

Живой сайт с админкой публикуется в Yandex Cloud. Адрес печатает выкладка, админка — `/admin` на том же адресе. GitHub Pages, https://blackojack.github.io/gips-i-plamya/, остаётся снимком последней сборки: там нет формы и свежих правок из админки.

## Команды

```bash
npm install
npm test
npm run admin:dev   # локальный API на 127.0.0.1:8787, пароль local-admin
npm run dev         # http://localhost:4321
npm run build
npm run deploy:yandex
```

Локальная админка: http://localhost:4321/admin. Без `admin:dev` сайт открывается как обычная сборка.

## Админка

На `/admin` правятся:

- тексты главной, шаги заказа, абзац о мастерской, пустая полка и подписи карточки;
- ссылка Telegram (пустая прячет кнопки «Написать»);
- полки: название, подпись, порядок, новая полка с латинским адресом;
- изделия: цена, описание, фото, порядок, «на главной», публикация и удаление.

Черновик на сайте не виден. Чтобы опубликовать, нужны фото, короткая строка и описание. Первое фото — обложка. Цена пустая показывает «Цену напишем в переписке».

Пароль задаётся секретом `ADMIN_PASSWORD` и в страницы не попадает.

## Что остаётся в репозитории

Папка изделия в `src/content/products` — начальное наполнение и снимок GitHub Pages. Папка `_primer` не публикуется. При выкладке новое изделие из репозитория добавляется в админку, только если такого адреса ещё нет. Уже сохранённые в админке поля выкладка не затирает.

Город, почту и оплату не добавляем, пока их не назвали. Фото мастерской на главной лежат в `src/assets/brand`.

## Публикация

Оба адреса собирает `.github/workflows/deploy.yml` после пуша в `main`.

### GitHub Pages

1. Репозиторий `BlackoJack/gips-i-plamya`, ветка `main`.
2. Settings → Pages → Source: **GitHub Actions**.
3. Workflow сам подставляет адрес и подпапку `/gips-i-plamya/`.

### Яндекс

В секретах репозитория нужны `YC_SA_JSON`, `YC_FOLDER_ID`, `YC_STORAGE_KEY` и `ADMIN_PASSWORD`. Без них Pages всё равно выйдет, а шаг Яндекса остановится и напишет, какого секрета нет.

Локально один раз: `yc init`, платёжный аккаунт на каталоге, `npm run deploy:yandex`. Скрипт заведёт бакеты, функцию и шлюз. Потом `bash scripts/github-secrets.sh` переносит ключи в GitHub (`gh auth login` уже должен быть выполнен). Для секрета `YC_SA_JSON` нужен файл `yandex/.ci-key.json` — ключ сервисного аккаунта, которому можно создавать ресурсы в каталоге.

Дальше пуш в `main` обновляет и Pages, и Яндекс. Правки из админки при этом не сбрасываются.
